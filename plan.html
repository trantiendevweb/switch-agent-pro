Cách bạn điều khiển

Bốn mặt, cùng một lõi

Terminal → 2D → workflow board → 3D. Cả bốn đều dùng thật được và cấu hình được — không mặt nào chỉ để ngắm.

1 · Terminal CLI + TUI

Mặt đầy đủ nhất. Chạy được qua SSH, nhét vào script và CI. Bảng chọn đánh số như thời tk.

2 · Dashboard 2D

Nhìn nhanh phiên nào chạy, hạn mức, chi phí. Bật/dừng phiên, duyệt approval, đọc log đã che secret.

3 · Workflow board

Kéo nối node dựng flow nhiều bước. Ghi thẳng ra flows.toml — file vẫn là nguồn sự thật, sửa tay được.

4 · 3D

Toàn cảnh đội agent. Cũng điều khiển được — bấm orb để dừng hoặc duyệt đúng phiên đó, không chỉ để ngắm.

Ba luật giữ cho bốn mặt không vỡ:
1. Một hợp đồng duy nhất — mọi hành động qua API lõi có version; CLI cũng chỉ là client đầu tiên.
2. Ngang quyền — tính năng chưa xong nếu chưa làm được từ CLI. UI được phép dễ hơn, không được là cách duy nhất.
3. Sự thật đến từ event — cấm UI tự đoán trạng thái bằng timer hay animation.

Cam kết

Mã nguồn mở, cấu hình theo từng dự án

Mở thật, không có bản pro

MIT, toàn bộ mã trong repo. Không telemetry, không tài khoản, không dịch vụ đám mây bắt buộc — clone về chạy offline. Mọi phụ thuộc đều mã nguồn mở, ghi trong ledger.

Mỗi dự án một kiểu

Tầng cấu hình: mặc định → global → .sagent/project.toml → cờ dòng lệnh. Project tự chọn mặt mặc định, cột hiển thị, flow ghim, route AI, giới hạn song song, hành động nào cần duyệt.

Kiến trúc

Tách bạch, không gộp

Bài học đắt nhất: không được nhét mọi thứ vào một struct "provider" duy nhất.

Agent Harness

CLI chính thức: Claude Code, Codex, Gemini CLI, Cursor. Giao tiếp qua ACP hoặc PTY.

AI Provider + Model

API trực tiếp; model và capability lưu riêng, không hardcode theo tên provider.

Auth Profile

subscription · oauth · api_key · service_account · local. Secret lưu tách khỏi config thường.

Model Route

provider + model + auth + chính sách fallback / health / chi phí.

Flow DAG

Khai báo được, resume sau restart, có approval gate không thể bỏ qua.

Workspace

thư mục · Git worktree · sandbox — mỗi session một chỗ làm riêng, không giẫm nhau.

Luật bất khả xâm phạm: dashboard không đọc token/API key · workflow chỉ cầm auth_profile_id/route_id · harness không biết dashboard tồn tại.

Bước 0 · Đổi tên xong
Module switch-agent-pro, lệnh sagent, mọi import + CI + script cài. Build/vet/test xanh.
Pha 0 · Đo giả định đang chạy
Chứng minh cơ chế cả hai đường trước khi khoá interface.
  • ✅ Windows/Claude: junction không cần admin · token là file · xoá an toàn
  • ⬜ Linux: token ở file hay keyring (rủi ro #1)
  • ⬜ Codex / Gemini CLI / Cursor · ⬜ 6 API provider · ⬜ threat model
Mỗi kết luận có command + OS + output đã redaction; chưa đo = unknown.
Pha 1 · Domain + SQLite + 2 lát cắt một phần
Lõi có domain rõ, storage an toàn, một lát cắt subscription + một lát cắt API.
  • ✅ Đổi/chạy tài khoản Claude trên Windows · bỏ Python · xoá an toàn có test
  • ⬜ internal/domain + internal/store (SQLite là nguồn sự thật)
  • ⬜ Claude thành Harness Adapter + conformance · ⬜ lát cắt API đầu tiên
CI Win+Linux xanh · đổi profile không đăng nhập lại · fault injection không tạo DB dở.
Pha 2 · Chạy song song một phần
Kiến trúc đường gọn: một binary, không daemon; SQLite giữ state (PID chỉ là thuộc tính runtime).
  • ✅ fleet bật N phiên nền · status · stop · clean
  • ✅ clone: mỗi phiên một config dir riêng → không đua ghi .claude.json
  • ✅ Cảnh báo thẳng: tiêu hạn mức gấp N · concurrent refresh chưa đo
  • ⬜ Git worktree cho từng phiên · .sagent/project.toml
Đã đo trên Windows: spawn nền, tự dọn phiên chết, stop giết cả cây con, xoá clone không xuyên junction.
Pha 2.5 · Codex + OpenAI-compatible
Chứng minh kiến trúc không bị đo ni theo Claude/Anthropic.
Hai harness dùng chung session API; hai protocol dùng chung route API.
Pha 3 · Flow DAG ghép được
Người dùng định nghĩa workflow mới mà không sửa mã Go.
  • Node: agent · model · shell · test · review · approve · merge · notify
  • 3 flow mẫu: fanout · squad · agents
Flow đang chạy tiếp tục sau restart · approval không thể bị bỏ qua.
Pha 4 · Mở rộng harness + AI API
Gemini CLI, Cursor · Grok, DeepSeek, OpenRouter, Mistral, Groq, Ollama/LocalAI.
Thêm provider chỉ khác endpoint bằng manifest · fallback không mất usage/error gốc.
Pha 5 · Bốn mặt điều khiển
Làm từ gần lõi ra ngoài, để hợp đồng API được thử lửa trước khi vẽ đẹp.
  • 5a API lõi có version + luồng event + TUI (bảng chọn như tk)
  • 5b Dashboard 2D — bật/dừng phiên, duyệt approval, log đã che secret
  • 5c Workflow board — dựng flow bằng giao diện, ghi ra flows.toml
  • 5d Cấu hình [ui] theo từng project
Mỗi hành động của UI đều có lệnh CLI tương đương — có test bắt buộc.
Pha 6–7 · Mặt 3D → phát hành
3D là projection của cùng event model, và cũng điều khiển được (bấm orb để dừng/duyệt). Rồi hardening: migration, ACL, symlink escape, SBOM, signed release.
Tắt mặt nào lõi vẫn chạy · UI phản ánh event thật, không đoán bằng animation timer.

Sòng phẳng

Đang bị chặn bởi

Chưa có máy/VM Linux: không đo được token Linux nằm ở file hay keyring — nếu là keyring thì nguyên lý "tách thư mục = tách tài khoản" gãy trên Linux. Nhãn Linux giữ experimental.
Chưa có API key để đo: toàn bộ đường API (route, streaming, usage/cost, fallback) chưa verify được. Cần key local-only, output redaction.
Hạn mức khi chạy song song: N phiên trên một tài khoản tiêu hạn mức gấp N — công cụ cảnh báo rõ, không giấu. Dùng nhiều tài khoản để vượt hạn mức có thể đi ngược ToS; bạn tự cân.
